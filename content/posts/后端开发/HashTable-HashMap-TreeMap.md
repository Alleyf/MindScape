# 1 二叉树

## 1.1 二叉搜索树

- **定义**：又称二叉查找树、有序二叉树或排序二叉树，是常用的一种二叉树类型。
- **核心性质**：对于树中任意节点，其**左子树**所有节点的值**小于**该节点值，**右子树**所有节点的值**大于**该节点值。

> 每一层最多有2^n个节点

## 1.2 红黑树

- **定义**：红黑树（Red Black Tree）是一种自平衡的二叉搜索树（BST）。
- **曾用名**：早期被称为平衡二叉B树（Symmetric Binary B-Tree）。

*特点*：
1. **颜色特性**：节点非红即黑。
2. **根节点特性**：根节点必须是黑色。
3. **叶子节点特性**：叶子节点（通常指空节点）都是黑色的。
4. **红节点特性**：红色节点的子节点必须为黑色（即不允许出现两个连续的红色节点）。
5. **黑高特性**：从任一节点到其每个叶子节点的所有路径都包含相同数目的黑色节点。

*时间复杂度*：
- **查找**：作为一棵二叉搜索树（BST），查找操作的时间复杂度为 **O(log n)**。
- **添加**：首先通过 O(log n) 的时间找到插入位置；插入完成后，仅需 O(1) 的旋转调整即可修复平衡。整体复杂度为 **O(log n)**。
- **删除**：首先通过 O(log n) 的时间找到被删除元素的位置；删除完成后，仅需 O(1) 的旋转调整即可修复平衡。整体复杂度为 **O(log n)**。

*旋转方法*：

> 1. **左旋**：把右孩子（X）提上来当爹，自己（P）变成左孩子。
> 2. **右旋**：把左孩子（X）提上来当爹，自己（P）变成右孩子。

# 2 散列表

- **定义**：散列表（Hash Table），又名哈希表或Hash表，是一种根据键（Key）直接访问内存存储位置的值（Value）的数据结构。
- **本质与原理**：它是由数组演化而来，利用了数组支持通过下标进行随机访问的特性。
- **散列函数定义**：将键（Key）映射为数组下标的函数，表示为 `hashValue = hash(key)`。
- **基本要求**：
    - **非负输出**：计算得到的散列值必须是大于等于 0 的整数，以作为数组下标。
    - **确定性**：如果两个键相等（`key1 == key2`），那么它们的哈希值也必然相同（`hash(key1) == hash(key2)`）。
    - **均匀性要求**：理想情况下，如果两个键不相等（`key1 != key2`），它们的哈希值也应不相同（`hash(key1) != hash(key2)`）。

## 2.1 哈希冲突-拉链法

- **核心术语**：在散列表中，数组的每个下标位置被称为**桶（bucket）**或**槽（slot）**。
- **解决方法**：每个桶对应一条**链表**。
- **存储机制**：当出现散列冲突时，将所有散列值相同的元素都放入同一个桶所对应的链表中。
- **查找与删除操作**：通过散列函数计算元素对应的槽位，然后遍历该槽位的链表进行查找或删除。
- **时间复杂度分析**：
    - **平均情况**：时间复杂度为 **O(1)**。
    - **最坏情况**：当散列冲突严重时，散列表可能退化为一条链表，时间复杂度退化为 **O(n)**。
- **优化方案**：可以将链表法中的链表改造为更高效的动态数据结构（`如红黑树`），此时查询时间复杂度可优化为 **O(log n)**。
- **防御DDoS攻击**：将链表法中的链表改造为红黑树，是防止DDoS攻击的重要手段。
- **DDoS攻击定义**：分布式拒绝服务攻击（Distributed Denial of Service），指多个攻击者（或一个攻击者控制的多台机器）在不同位置同时向一个或多个目标发起攻击。
- **攻击特点**：攻击的发出点是分布式的，攻击者可以有多个。

## 2.2 哈希冲突-开放寻址法

- **核心思想**：当出现散列冲突时，不再创建链表，而是继续在数组的空白位置中寻找另一个空闲槽位来存储冲突的元素。
- **探测方式**：通过一定的探测策略（如线性探测、二次探测、双重散列等）在数组中逐个查找下一个可用的空闲位置。
- **查找操作**：根据相同的探测序列查找元素，如果遇到空闲槽位则说明元素不存在。
- **删除注意事项**：删除元素时不能直接清空，通常需要特殊标记（如标记为"已删除"），否则可能影响后续元素的查找。
- **优缺点**：
    - 优点：数据都存储在数组中，内存连续，CPU缓存友好。
    - 缺点：对装载因子敏感，当空闲槽位较少时，探测时间会显著增加；删除操作相对复杂；元素总数不能超过数组大小。

# 3 HashMap

## 3.1 基本原理

- **HashMap数据结构**：底层采用哈希表，即**数组 + 链表/红黑树**的组合。
- **存储（put）原理**：
    1. 根据key的`hashCode()`重新计算hash值，确定元素在数组中的下标。
    2. 若该下标无元素，直接存入。
    3. 若该下标已有元素（哈希冲突）：
        - 如果key相同，则覆盖原值。
        - 如果key不同，则将键值对加入链表或红黑树。
- **获取（get）原理**：通过hash值定位到数组下标，再遍历链表或红黑树，通过`equals()`比较key找到对应值。

## 3.2 HashMap的jdk1.7和jdk1.8有什么区别

**1.7**：采用拉链法（数组+链表）。
**1.8**：引入红黑树优化。当**链表长度 > 8**且**数组长度 ≥ 64**时，链表转为红黑树，减少搜索时间；当红黑树节点数 ≤ 6 时（扩容拆分时），退化为链表。
