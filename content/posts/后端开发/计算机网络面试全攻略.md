# 1 🌐 计算机网络面试全攻略 (0 -> 1)

## 1.1 第一阶段：基础基石 (必问必会)

*目标：展示你对网络分层和寻址机制的深刻理解，这是所有高级话题的地基。*

### 1.1.1 OSI 七层模型 Vs TCP/IP 四层模型

*   **OSI 七层**：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。
*   **TCP/IP 四层**：网络接口层、网际层 (IP)、传输层 (TCP/UDP)、应用层。
*   **面试考点**：
    *   数据封装与解封装过程（加头/去头）。
    *   各层典型协议：
        *   L2: Ethernet, MAC, VLAN, Switch。
        *   L3: IP, ICMP (Ping), ARP, Router, NAT。
        *   L4: TCP, UDP。
        *   L7: HTTP, DNS, SSH, FTP, TLS。
    *   **区别**：OSI 是理论标准，TCP/IP 是事实标准；会话层和表示层在 TCP/IP 中通常合并到应用层 [[2]][[5]]。

### 1.1.2 IP 地址与子网划分

*   **IPv4 vs IPv6**：
    *   IPv4 枯竭问题，NAT (网络地址转换) 的作用与弊端（破坏端到端连接）。
    *   IPv6 的优势：海量地址、简化头部、内置 IPSec、无状态自动配置 (SLAAC) [[30]]。
*   **子网掩码与 CIDR**：
    *   如何计算网络号、广播地址、可用主机数？
    *   **VLSM** (可变长子网掩码) 的应用。
*   **ARP 协议**：如何通过 IP 获取 MAC 地址？ARP 欺骗原理及防御。

### 1.1.3 DNS (域名系统) - 互联网的通讯录

*   **解析流程**：浏览器缓存 -> 本地 Hosts -> 本地 DNS (LDNS) -> 根域名 -> 顶级域名 -> 权威域名 (迭代 + 递归查询)。
*   **记录类型**：A (IPv4), AAAA (IPv6), CNAME (别名), MX (邮件), TXT (验证/SPF)。
*   **优化**：DNS 预取、HTTPDNS (防止劫持、调度优化)、CDN 中的 DNS 负载均衡。
*   **考点**：输入 URL 到页面展示，DNS 在其中扮演什么角色？延迟如何优化？[[9]]

## 1.2 第二阶段：核心传输协议 (重中之重)

*目标：TCP 是面试的深水区，必须掌握状态机、拥塞控制和可靠性保证。*

### 1.2.1 TCP Vs UDP

| 特性 | TCP | UDP |
| :--- | :--- | :--- |
| **连接** | 面向连接 | 无连接 |
| **可靠性** | 可靠 (确认、重传、排序) | 不可靠 (尽最大努力交付) |
| **速度** | 较慢 (头部大、机制多) | 快 (头部小、无阻塞) |
| **场景** | 文件传输、邮件、Web (HTTP) | 视频直播、语音通话、DNS、QUIC |
| **流量控制** | 滑动窗口 | 无 |

### 1.2.2 TCP 三次握手与四次挥手 (必背图解)

*   **三次握手**：
    1.  SYN (Client -> Server)
    2.  SYN + ACK (Server -> Client)
    3.  ACK (Client -> Server)
    *   **为什么是三次？** 防止已失效的连接请求突然传到服务器，产生错误初始化；同步双方序列号。
*   **四次挥手**：
    1.  FIN (Client -> Server)
    2.  ACK (Server -> Client) —— *此时连接处于 HALF_CLOSE 状态*
    3.  FIN (Server -> Client) —— *服务器数据发送完毕*
    4.  ACK (Client -> Server)
*   **状态机考点**：
    *   **TIME_WAIT**：为什么客户端要等待 2MSL？(确保最后一个 ACK 到达，防止旧连接干扰新连接)。大量 TIME_WAIT 如何优化？(内核参数调整)。
    *   **CLOSE_WAIT**：通常是代码问题，应用层未调用 `close()`。
    *   **SYN Flood 攻击**：利用半连接队列耗尽资源，防御方案 (SYN Cookie)。

### 1.2.3 TCP 可靠性与性能优化

*   **超时重传**：RTO (Retransmission TimeOut) 的动态计算。
*   **滑动窗口**：流量控制，防止接收方缓冲区溢出。
*   **拥塞控制** (四大算法)：
    *   慢启动 (Slow Start)
    *   拥塞避免 (Congestion Avoidance)
    *   快重传 (Fast Retransmit)
    *   快恢复 (Fast Recovery)
*   **粘包/拆包**：原因 (TCP 是流协议) 及解决方案 (固定长度、分隔符、Length 字段)。

## 1.3 第三阶段：应用层协议演进 (高频热点)

*目标：展示你对 Web 性能演进的认知，特别是 HTTP/3 和 QUIC，这是 2026 年的面试分水岭 [[13]][[15]]。*

### 1.3.1 HTTP 协议演进史

*   **HTTP/1.0**：短连接，每次请求建立一次 TCP。
*   **HTTP/1.1**：
    *   **Keep-Alive** (长连接)。
    *   **Host 字段** (虚拟主机)。
    *   **缺陷**：**队头阻塞 (Head-of-Line Blocking)**。一个请求阻塞，后续请求即使准备好也无法发送。
*   **HTTP/2** (基于 TCP)：
    *   **多路复用** (Multiplexing)：同一连接并发多个请求，解决应用层队头阻塞。
    *   **二进制分帧**：更高效的解析。
    *   **头部压缩** (HPACK)。
    *   **服务器推送** (Server Push)。
    *   **遗留问题**：TCP 层面的队头阻塞依然存在 (一个包丢失，整个 TCP 窗口等待重传)。
*   **HTTP/3** (基于 **QUIC/UDP**) - **2026 年重点**：
    *   **彻底解决队头阻塞**：基于 UDP，每个流独立可靠传输，丢包只影响当前流。
    *   **0-RTT 建连**：利用之前会话信息，首次握手即可发送数据，极大降低延迟 [[10]][[16]]。
    *   **连接迁移**：IP 变化 (如 WiFi 切 4G) 不需要重新握手，通过 Connection ID 保持连接。
    *   **内置 TLS 1.3**：安全性默认集成，不再需要单独升级 TLS。

### 1.3.2 HTTPS 与 TLS 安全

*   **TLS 1.2 vs TLS 1.3** (2026 年主流)：
    *   **握手更快**：TLS 1.3 只需 1-RTT (甚至 0-RTT)，TLS 1.2 需 2-RTT [[25]][[28]]。
    *   **更安全**：移除了不安全算法 (RSA 密钥交换、SHA-1, RC4)，强制使用前向保密 (PFS) [[19]][[21]]。
    *   **加密范围扩大**：TLS 1.3 加密了更多握手信息 (如证书)，保护隐私。
*   **对称加密 vs 非对称加密**：HTTPS 混合使用 (非对称交换密钥，对称传输数据)。
*   **中间人攻击 (MITM)**：原理及 CA 证书链验证机制。

## 1.4 第四阶段：进阶架构与云原生网络

*目标：展示你在分布式系统和云环境下的网络视野。*

### 1.4.1 负载均衡 (Load Balancing)

*   **层级**：
    *   **L4 (TCP/UDP)**：Nginx (Stream 模块), LVS, F5。性能好，基于 IP+Port。
    *   **L7 (HTTP)**：Nginx, HAProxy, Envoy。基于 URL/Cookie/Header，功能丰富。
*   **算法**：轮询、加权轮询、最少连接、一致性哈希 (用于缓存命中)。

### 1.4.2 CDN (内容分发网络)

*   **原理**：将静态资源缓存到边缘节点，用户就近访问。
*   **关键**：DNS 调度、缓存策略 (Cache-Control, ETag)、回源机制。

### 1.4.3 云原生网络 (Kubernetes Networking)

*   **CNI 插件**：Flannel, Calico, Cilium (eBPF)。
*   **Service 发现**：ClusterIP, NodePort, LoadBalancer, Ingress。
*   **Service Mesh**：Istio (Sidecar 模式)，将网络治理 (熔断、限流、监控) 下沉到基础设施层。
*   **eBPF**：2026 年热门技术，在内核态高效处理网络包，用于高性能代理和安全监控 [[35]]。

### 1.4.4 WebSocket 与 SSE

*   **WebSocket**：全双工通信，适合即时聊天、游戏。握手基于 HTTP，升级协议。
*   **SSE (Server-Sent Events)**：单向服务器推送，基于 HTTP，实现简单。

## 1.5 第五阶段：实战排查与场景题 (区分度关键)

*目标：展示你解决真实问题的能力，而非纸上谈兵。*

### 1.5.1 经典面试题：“在浏览器输入 URL 并回车，发生了什么？”

*   **满分回答路径**：
    1.  **URL 解析**：检查协议、域名、路径。
    2.  **DNS 解析**：多级缓存 -> 递归/迭代查询 -> 得到 IP。
    3.  **TCP 连接**：三次握手 (SYN, SYN-ACK, ACK)。
    4.  **TLS 握手** (如果是 HTTPS)：协商密钥，验证证书 (TLS 1.3 优化)。
    5.  **发送 HTTP 请求**：构建 Request 报文 (Headers, Body)。
    6.  **服务器处理**：负载均衡 -> Web 服务器 (Nginx) -> 应用服务器 (Tomcat/Node) -> 数据库。
    7.  **返回响应**：HTTP 状态码 (200, 301, 404, 500)。
    8.  **浏览器渲染**：HTML 解析 -> DOM 树 -> CSSOM -> Render Tree -> Layout -> Paint。
    9.  **断开连接**：四次挥手 (或 Keep-Alive 保持)。

### 1.5.2 故障排查思路 (Troubleshooting)

*   **工具链**：
    *   `ping` / `traceroute` (连通性/路由)。
    *   `telnet` / `nc` (端口通断)。
    *   `curl` / `wget` (模拟请求，看 Header/耗时)。
    *   `tcpdump` / `Wireshark` (抓包分析，终极手段)。
    *   `netstat` / `ss` (查看连接状态，如 TIME_WAIT 数量)。
    *   `dig` / `nslookup` (DNS 调试)。
*   **常见场景**：
    *   **网站访问慢**：DNS 解析慢？TCP 建连慢 (网络延迟)？TTFB 长 (服务端处理慢)？内容下载慢 (带宽瓶颈)？
    *   **连接重置 (Connection Reset)**：服务端进程挂了？防火墙拦截？ backlog 队列满？
    *   **跨域问题 (CORS)**：浏览器同源策略，服务端需设置 `Access-Control-Allow-Origin`。

### 1.5.3 2026 年新趋势考点

*   **QUIC 的落地**：为什么抖音/TikTok、YouTube 大力推行 QUIC？(弱网环境下的体验提升)。
*   **IPv6 的普及**：双栈部署策略。
*   **零信任网络 (Zero Trust)**：不再信任内网，所有访问需认证 (mTLS)。
*   **DDoS 攻击防御**：流量清洗、Anycast 技术。
