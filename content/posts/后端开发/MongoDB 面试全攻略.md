# 1 🚀 MongoDB 面试全攻略 (0 -> 1)

## 1.1 第一阶段：基础概念 (必问必会)

*目标：展示你对数据库选型和基本操作的理解。*

### 1.1.1 什么是 MongoDB？它与传统关系型数据库 (RDBMS) 有什么区别？

*   **核心定义**：MongoDB 是一个基于分布式文件存储的文档型数据库（NoSQL），数据以 **BSON** (Binary JSON) 格式存储。
*   **对比 RDBMS**：
    *   **数据模型**：文档 (Document/Collection) vs 行/表 (Row/Table)。
    *   **Schema**：动态模式 (Schema-less) vs 固定模式 (Fixed Schema)。
    *   **关联查询**：支持 `$lookup` (类似 Join)，但推荐通过嵌入文档或应用层关联来优化性能，不鼓励复杂 Join。
    *   **事务**：早期版本不支持多文档事务，4.0+ 已支持多文档 ACID 事务。
    *   **扩展性**：原生支持水平扩展 (Sharding) vs RDBMS 通常依赖垂直扩展或中间件分库分表。

### 1.1.2 核心术语映射

| RDBMS | MongoDB |
| :--- | :--- |
| Database | Database |
| Table | Collection |
| Row | Document |
| Column | Field |
| Index | Index |
| Primary Key | `_id` (默认自动生成 ObjectId) |

### 1.1.3 数据类型与 BSON

*   了解常见类型：`String`, `Integer`, `Boolean`, `Double`, `Date`, `Array`, `Object`, `ObjectId`。
*   **ObjectId 结构**：12 字节 = 4 字节时间戳 + 3 字节机器码 + 2 字节进程 ID + 3 字节计数器。这解释了为什么它是大致有序且唯一的。

## 1.2 第二阶段：架构与原理 (进阶核心)

*目标：展示你懂底层机制，能解决复杂问题。*

### 1.2.1 存储引擎 (Storage Engine)

*   **WiredTiger** (默认)：
    *   支持**文档级锁** (Document-level locking)，并发写入性能极高。
    *   支持压缩 (Snappy, zlib)。
    *   使用 **Checkpoint** 机制将内存数据刷盘，配合 **Journal** (预写日志) 保证崩溃恢复。
*   **MMAPv1** (旧版)：集合级锁，已基本淘汰，面试中提到即可，强调现在都用 WiredTiger。

### 1.2.2 索引机制 (Indexing)

*   **B-Tree**：MongoDB 默认使用 B-Tree 索引。
*   **常见索引类型**：
    *   单键索引、复合索引 (注意**最左前缀原则**)。
    *   多键索引 (数组字段)。
    *   文本索引 (全文搜索)。
    *   地理空间索引 (2dsphere, 用于地图应用)。
    *   TTL 索引 (自动过期删除，如日志、验证码)。
*   **覆盖查询 (Covered Query)**：查询的字段全部包含在索引中，无需回表扫描文档，速度极快。

### 1.2.3 聚合框架 (Aggregation Framework)

*   这是 MongoDB 的数据处理核心。
*   **Pipeline 概念**：数据像流水一样经过多个阶段 (`$match`, `$group`, `$sort`, `$project`, `$lookup`, `$unwind`)。
*   **面试考点**：如何优化聚合管道？(尽早 `$match` 过滤数据，利用索引排序)。

### 1.2.4 复制集 (Replica Set) - 高可用

*   **架构**：1 个 Primary (主节点，负责写) + N 个 Secondary (从节点，负责读/备份) + (可选) Arbiter (仲裁者，只投票)。
*   **选举机制**：基于 **Raft** 协议变种。当主节点挂掉，从节点发起选举，票数过半者成为新主。
*   **读写分离**：通过 `ReadPreference` 设置读取策略 (Primary, PrimaryPreferred, Secondary, etc.)。
*   **Oplog**：操作日志，主节点将写操作记录到 oplog，从节点异步拉取并重放，实现数据同步。

### 1.2.5 分片集群 (Sharding) - 水平扩展

*   **适用场景**：数据量巨大 (TB/PB 级)，单机无法承载。
*   **核心组件**：
    *   **Shard**：实际存储数据的分片节点 (通常是复制集)。
    *   **Mongos**：路由服务，客户端连接入口，负责分发请求。
    *   **Config Server**：存储集群元数据 (分片规则、块分布)。
*   **片键 (Shard Key) 选择** (高频考点)：
    *   **基数大**：避免数据倾斜。
    *   **写入频率均匀**：避免热点。
    *   **常用策略**：范围分片 (Range)、哈希分片 (Hash)、标签分片 (Tagged)。
    *   **错误示范**：使用时间戳作为片键会导致“热点写入” (所有新数据都写入最后一个分片)。

## 1.3 第三阶段：性能优化与实战 (区分度关键)

*目标：展示你有实际生产环境排查问题的能力。*

### 1.3.1 慢查询分析

*   开启 **Profiler**。
*   使用 `explain("executionStats")` 分析查询计划。
*   **关键指标**：
    *   `IXSCAN` (走索引) vs `COLLSCAN` (全表扫描，必须避免)。
    *   `nReturned` / `totalDocsExamined` (返回数/扫描数，比值越接近 1 越好)。
    *   `executionTimeMillis`。

### 1.3.2 内存管理

*   MongoDB 极度依赖内存。WiredTiger 会使用空闲内存作为缓存 (Cache)。
*   如果内存不足，会发生频繁的 Page Faults，导致性能急剧下降。

### 1.3.3 写入优化

*   **Write Concern**：控制数据持久化级别。
    *   `w: 1` (默认，主节点确认即返回，快但有丢失风险)。
    *   `w: "majority"` (多数节点确认，安全但慢，保证不丢失)。
*   **Bulk Write**：批量插入比单条插入快得多。

### 1.3.4 设计模式 (Schema Design)

*   **嵌入 (Embedding)** vs **引用 (Referencing)**：
    *   **嵌入**：数据经常一起读取，一对少关系 (如：订单和订单项)。优势：读取快，原子性。劣势：文档大小限制 (16MB)。
    *   **引用**：多对多关系，数据独立增长，或子文档过大。优势：灵活，无大小限制。劣势：需要应用层 Join 或 `$lookup`。

## 1.4 第四阶段：高频面试题清单 (模拟演练)

### 1.4.1 基础题

1.  MongoDB 的 `_id` 是怎么生成的？有什么特点？
2.  简述一下 MongoDB 的更新操作 (`$set`, `$inc`, `$push`, `$addToSet`)。
3.  什么是 TTL 索引？应用场景有哪些？

### 1.4.2 进阶题

4.  **复合索引的最左前缀原则在 MongoDB 中是如何工作的？** (例如：索引 `{a:1, b:1}`，查询 `{b:1}` 能用到索引吗？不能。查询 `{a:1}` 可以。)
5.  **复制集中，如果主节点挂了，会发生什么？** (选举过程，数据一致性如何保证？)
6.  **分片集群中，片键选择错误会导致什么问题？** (数据倾斜、热点写入、查询广播风暴。)
7.  **MongoDB 如何实现事务？** (4.0+ 支持多文档事务，基于快照隔离，但在分片环境下有性能开销，需谨慎使用。)

### 1.4.3 场景/优化题

8.  **有一个查询非常慢，你如何排查和优化？**
    *   *回答思路*：查看慢查询日志 -> 使用 explain 分析 -> 检查是否全表扫描 -> 检查索引是否命中/顺序是否正确 -> 检查数据结构是否需要重构 (嵌入改引用或反之)。
9.  **海量数据迁移方案？**
    *   *回答思路*：`mongodump/mongorestore` (小数据), `mongoimport/export`, 双写方案 (代码层同时写新旧库，后台同步历史数据，验证后切换)。
10. **如何保证数据不丢失？**
    *   *回答思路*：复制集 `w: majority` + `j: true` (journal 落盘)；定期备份；合理的运维监控。

## 1.5 第五阶段：避坑指南与最佳实践

*   **不要滥用 `$lookup`**：虽然支持 Join，但大规模数据关联性能较差，尽量在数据建模阶段处理好关系。
*   **文档大小限制**：单个文档最大 16MB，设计时需考虑数组是否会无限增长。
*   **正则查询陷阱**：`/^abc/` 可以用索引，但 `/.*abc.*/` (前缀通配) 会导致全表扫描。
*   **跳过分页问题**：`skip().limit()` 在深分页时性能极差，建议使用“基于游标”的分页 (记录上一页最后一条数据的 `_id`，查询 `_id > last_id`)。

## 1.6 💡 备考建议

1.  **动手实践**：不要只背概念。安装一个本地 MongoDB，尝试创建复制集，插入百万级数据，执行 `explain` 看看效果。
2.  **结合项目**：准备 1-2 个你在项目中如何使用 MongoDB 的案例（例如：用做日志存储、商品详情缓存、实时消息队列等），并说明遇到了什么挑战以及如何解决的。
3.  **关注版本**：面试时最好提及你熟悉的是 4.4, 5.0 还是 6.0+ 版本，因为新特性（如时间序列集合、向量搜索）在不同版本差异较大。
