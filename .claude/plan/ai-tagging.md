# MindScape 浏览器端 AI 自动打标签功能规划

## 已明确的决策

- **技术栈**: React 19 + Vite 8 + TypeScript
- **现有架构**: 纯前端 SPA，使用 `import.meta.glob` 在构建时加载 markdown 文件
- **内容语言**: 中文为主（大量中文技术博客）
- **标签字段**: `Note.tags: string[]`，目前手动添加
- **现有 AI 系统**: 已实现 `extractKeywords()` 方法调用远程 API 生成关键词

## 整体规划概述

### 项目目标

在浏览器端集成轻量级 AI 模型，实现文章标签的自动分析与推荐功能，用户可一键应用或修改 AI 推荐的标签。

### 技术栈

- **运行时**: 浏览器端 WebLLM (WebGPU 加速)
- **模型格式**: Llama.cpp 量化模型 (.gguf)
- **备选方案**: Transformers.js
- **包管理**: @mlc-ai/webllm 或 xenova/transformers

### 主要阶段

1. **技术调研与方案确定** - 评估 WebLLM/Transformers.js，确定最终技术方案和模型选择
2. **基础架构搭建** - 实现模型加载、缓存、推理服务层
3. **功能开发与集成** - 开发 AI 打标签 UI 和交互流程
4. **优化与验收** - 性能优化、测试验证、文档完善

## 需要进一步明确的问题

### 问题 1：模型加载策略

**推荐方案**：

- 方案 A：**惰性加载** - 用户首次点击"AI 打标签"时才加载模型
  - 优点：不影响首屏加载时间，不占用日常内存
  - 缺点：首次使用需要等待较长时间

- 方案 B：**预加载** - 在页面空闲时（如 `requestIdleCallback`）静默下载模型
  - 优点：用户点击时模型已就绪，体验更流畅
  - 缺点：占用日常内存，增加页面资源负担

### 问题 2：标签存储方式

**推荐方案**：

- 方案 A：**直接写入 frontmatter** - 自动将 AI 标签写入 markdown 文件的 frontmatter
  - 优点：持久化保存，无需额外存储
  - 缺点：需要文件系统写入权限（纯前端 SPA 无法实现，除非通过 Git API）

- 方案 B：**本地 IndexedDB 存储** - 将 AI 推荐标签存储在本地，与 markdown 的 frontmatter 分离
  - 优点：纯前端实现，无后端依赖
  - 缺点：标签仅存在于本地，换设备需重新生成

- 方案 C：**混合方案** - 本地缓存 + 导出功能（用户可导出带标签的 markdown）
  - 优点：兼顾灵活性和可移植性
  - 缺点：流程稍复杂

**等待用户选择**：

```
请选择您偏好的方案：
[ ] 方案 A：直接写入 frontmatter（需要后端或 Git API）
[ ] 方案 B：IndexedDB 本地存储
[ ] 方案 C：混合方案（本地缓存 + 导出）
[ ] 其他方案：_______________
```

### 问题 3：浏览器兼容性要求

**推荐方案**：

- 方案 A：**仅支持现代浏览器** - 要求 Chrome/Edge 113+、Firefox 121+（支持 WebGPU）
  - 优点：性能最优，可使用 WebGPU 加速
  - 缺点：Safari（macOS/iOS）用户无法使用

- 方案 B：**渐进增强** - 检测 WebGPU 支持，不支持时回退到 WebAssembly 或远程 API
  - 优点：覆盖更多用户
  - 缺点：需要维护多套 fallback 逻辑

**等待用户选择**：

```
[ ] 方案 B：渐进增强（支持更多浏览器，性能可能下降）
[ ] 其他方案：_______________
```

### 问题 4：模型大小和精度权衡

**推荐方案**：

- 方案 A：**Qwen2-0.5B-Instruct INT4 量化版** (~500MB)
  - 优点：体积小，加载快，中文支持良好
  - 缺点：推理质量略低于大模型

- 方案 B：**Qwen2-1.5B-Instruct INT4 量化版** (~1GB)
  - 优点：质量更好，泛化能力更强
  - 缺点：加载时间更长，内存占用更高

- 方案 C：**Phi-3-mini 4bit 量化版** (~900MB)
  - 优点：英语能力强，体积适中
  - 缺点：中文支持不如 Qwen2

## 验收标准

### 功能验收

- [ ] 用户点击"AI 打标签"后，能在 30 秒内（首次）或 5 秒内（非首次）获得标签推荐
- [ ] 生成的标签数量在 3-8 个之间，与文章内容相关
- [ ] 用户可接受全部标签、选择部分标签或手动编辑
- [ ] 标签生成过程有明确的进度提示
- [ ] 浏览器不支持时能优雅降级

### 性能验收

- [ ] 模型首次加载时间 < 30 秒（视网络而定）
- [ ] 推理速度 < 5 秒/文章
- [ ] 模型缓存后二次加载 < 3 秒
- [ ] 内存占用峰值 < 2GB

### 体验验收

- [ ] UI 与现有风格一致
- [ ] 错误提示友好，能引导用户重试
- [ ] 支持中断（用户可取消正在进行的推理）
