# MindScape 标签展示优化规划

## 已明确的决策

- **技术栈**: React + TypeScript + Vite SPA（单文件结构，所有页面在 `src/App.tsx`）
- **内容加载**: 通过 `import.meta.glob` 在构建时批量加载 `content/posts/**/*.md`
- **目录结构**: 现有 8 个子目录（后端开发、前端开发、运维开发、中间件和工具、算法学习、科研学习、艺术生活、开发工具）
- **主题系统**: Dark mode 默认，CSS custom properties 管理颜色
- **标签来源**: 每个 md 文件的 front matter `tags` 字段（数组）

## 整体规划概述

### 项目目标

优化 MindScape 博客的标签展示系统，解决当前标签过多难以浏览的问题。核心目标是实现按文章所属目录自动归类、可折叠展开、默认数量限制的标签展示方案，同时保持现有单标签筛选功能不变。

### 技术栈

- React (SPA)
- TypeScript
- CSS (global styles with CSS custom properties)
- Vite (构建工具)

### 主要阶段

1. **阶段一：数据层重构** - 提取标签与目录的关联逻辑，建立自动归类机制
2. **阶段二：TagsPage 重构** - 实现分类标签云，支持折叠/展开
3. **阶段三：NotesPage 优化** - 在标签筛选区域实现分类折叠展示
4. **阶段四：样式与交互优化** - 添加动画、平滑过渡等细节体验

### 详细任务分解

#### 阶段一：数据层重构

- **任务 1.1**：扩展 Note 类型，添加 `directory` 字段
  - 目标：从 slug 中自动提取目录名（如 `后端开发/Java八股` -> `后端开发`）
  - 输入：现有 `getNotes()` 函数
  - 输出：Note 对象新增 `directory` 属性
  - 涉及文件：`src/types/index.ts`、`src/utils/noteLoader.ts`
  - 预估工作量：1 小时

- **任务 1.2**：构建标签目录映射数据结构
  - 目标：建立 `Map<directory, Set<tag>>` 映射，自动收集每个目录下的所有标签
  - 输入：所有笔记的 tags 数组
  - 输出：目录 -> 标签集合的映射表
  - 涉及文件：`src/utils/noteLoader.ts`（新增工具函数）
  - 预估工作量：1 小时

- **任务 1.3**：设计目录分类 UI 数据结构
  - 目标：定义 `TagCategory` 接口，包含目录名、标签列表、默认折叠状态
  - 输入：目录标签映射
  - 输出：供 UI 组件使用的有序分类数组
  - 涉及文件：`src/types/index.ts`
  - 预估工作量：0.5 小时

```typescript
// 新增类型定义
interface TagCategory {
  id: string;           // 目录slug
  label: string;        // 显示名称（如"后端开发"）
  tags: Array<{
    name: string;
    count: number;
  }>;
  isExpanded: boolean;  // 折叠状态
}
```

#### 阶段二：TagsPage 重构

- **任务 2.1**：重写标签分类逻辑，替换硬编码分组
  - 目标：基于文章目录自动归类，替代现有的 `tagGroups` 硬编码
  - 输入：目录标签映射数据
  - 输出：动态生成的 `TagCategory[]`
  - 涉及文件：`src/App.tsx`（TagsPage 组件，约 813-926 行）
  - 预估工作量：2 小时

- **任务 2.2**：实现分类折叠/展开交互
  - 目标：每个分类可独立折叠和展开
  - 输入：用户点击分类标题或展开/收起按钮
  - 输出：更新对应分类的 `isExpanded` 状态
  - 涉及文件：`src/App.tsx`、`src/index.css`
  - 预估工作量：1.5 小时

- **任务 2.3**：实现默认数量限制 + 展开全部
  - 目标：每个分类默认显示前 5 个标签，点击"展开更多"显示全部
  - 输入：分类数据、用户点击事件
  - 输出：过滤后的可见标签列表 + "展开更多"按钮
  - 涉及文件：`src/App.tsx`、`src/index.css`
  - 预估工作量：1 小时

- **任务 2.4**：TagsPage UI 布局实现
  - 目标：按分类分块展示标签云，每个分类有序排列
  - 布局结构：
    ```
    [分类标题]              [展开/收起]
    #tag1(3) #tag2(5) #tag3(2)  ... [展开更多(12)]
    ```
  - 涉及文件：`src/index.css`（新增 `.tag-category-section`、`.tag-category-header`、`.tag-category-list` 等类）
  - 预估工作量：1.5 小时

#### 阶段三：NotesPage 优化

- **任务 3.1**：实现 NotesPage 标签筛选区分类展示
  - 目标：在笔记筛选区域（684-700 行）按目录分组展示标签
  - 输入：目录标签映射、当前选中标签
  - 输出：分组折叠的标签筛选 UI
  - 涉及文件：`src/App.tsx`（NotesPage 组件）
  - 预估工作量：2 小时

- **任务 3.2**：保持向后兼容
  - 目标：单标签选择、多标签筛选逻辑不变
  - 验证：点击标签仍能正确筛选笔记列表
  - 涉及文件：`src/App.tsx`（NotesPage 组件的 `toggleTag`、`selectedTags` 逻辑）
  - 预估工作量：0.5 小时

#### 阶段四：样式与交互优化

- **任务 4.1**：分类折叠/展开动画
  - 目标：使用 CSS transition 或 Framer Motion 实现平滑动画
  - 输入：折叠状态变化
  - 输出：高度从 0 到 auto 的平滑过渡
  - 涉及文件：`src/index.css`
  - 预估工作量：1 小时

- **任务 4.2**：响应式适配
  - 目标：移动端（<768px）分类单列显示，标签单行滚动
  - 涉及文件：`src/index.css`（现有响应式断点）
  - 预估工作量：0.5 小时

- **任务 4.3**：键盘导航与焦点管理
  - 目标：支持 Tab 键切换标签，Enter 键选中
  - 涉及文件：`src/App.tsx`
  - 预估工作量：0.5 小时

## 需要进一步明确的问题

### 问题 1：分类方式选择

**推荐方案**：

- 方案 A（按目录分类）：标签按文章所在目录分组（如"后端开发"目录下所有标签），与内容组织一致，用户容易理解
- 方案 B（按主题语义分类）：类似现有 `tagGroups`，按技术/思维/成长/生活等语义分组，但需要维护词库

**等待用户选择**：

```
请选择您偏好的方案：
[ ] 方案 A：按目录分类（自动归类，维护成本低）
[ ] 方案 B：按主题分类（语义更清晰，但需维护词库映射）
```

---

### 问题 2：默认折叠还是展开？

**推荐方案**：

- 方案 A（默认全部展开）：用户可立即看到所有标签，但首次加载可能较长
- 方案 B（默认全部折叠）：页面更整洁，用户按需展开
- 方案 C（混合模式）：默认展开第一个分类，其余折叠

**等待用户选择**：

```
请选择默认展示行为：
[ ] 方案 A：默认全部展开
[ ] 方案 B：默认全部折叠
[ ] 方案 C：只展开第一个分类，其余折叠
```

---

### 问题 3：每个分类默认显示几个标签？

**推荐方案**：

- 方案 A：每个分类默认显示 5 个标签
- 方案 B：每个分类默认显示 8 个标签
- 方案 C：按标签频率动态调整（高频标签多显示）

**等待用户选择**：

```
请选择每个分类的默认显示数量：
[ ] 方案 A：5 个
[ ] 方案 B：8 个
[ ] 方案 C：动态调整（按频率排序）
```

### 问题 4：TagsPage 是否保留原有的 tab 切换功能？

当前 TagsPage 有"全部、技术、思维、成长、生活"五个 tab，优化后是否需要保留这一层级切换？

**等待用户选择**：

### 问题 5：分类名称是否需要别名映射？

当前目录名（如"中间件和工具"）可能不够简洁，是否需要别名映射？

**等待用户选择**：

## 风险识别与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 目录结构变化导致分类不稳定 | 当用户移动文章到不同目录时，标签分类会改变 | 考虑使用 front matter 中的 `category` 字段作为备选 |
| 标签数量持续增长 | 未来标签可能超过 100 个 | 分类折叠机制可有效控制视觉复杂度 |
| 移动端分类展开占用大量屏幕 | 折叠内容展开后可能影响浏览 | 限制同时展开的分类数量 |
